## 3. 권장 제작 기간의 개선 기능 3가지

### 1순위 · 기록 타임라인과 필터

기존 기능: `event.at` 최신순, 접속(access)/XDR(xdr) 종류·업무 앱·접속 상태 3개 필터, 표시 건수/받은 건수, 사건 ID/근거/규칙 상세.

이번 개선: **사건 발생일(UTC) 기준 날짜 그룹**, 정렬 출처 명시, 다중 가상 기록의 정렬·교차 필터·선택 결과 없음·상세·미지원 조치 버튼 검증용 단위 테스트.

**조회 시각과 사건 시각을 혼동하지 않는다.** 현재 제공 `public/app.js`의 `studentData('events')`는 기록의 `status`/`mode`/`data`/`error`만 전달하며, 개별 기록의 조회 확인 시각을 전달하지 않는다. `event.at`은 사건 발생 시각이다. 따라서 현재 코드는 요청한 '조회 시각 순서'를 **실제 조회 시각으로 구현했다고 주장하지 않고**, 사건 발생 시각 최신순을 유지한다. 새 화면에서 그 차이를 드러낸다. 실제 조회 확인 시각 기준 정렬은 **제공 계약에 승인된 시간 메타데이터가 추가되기 전까지 보류**한다.

### 2순위 · 보호 상태 표시

- 원천의 `loading`/`ok`/`error`/`unknown`과 Demo·연결 없음 정보를 구별한다.
- **주의 알림 정보 자체가 없는 경우**와 **전달받은 알림 목록이 빈 배열인 경우**를 별도로 표시한다. 알림 0건을 '보안 정상'으로 표시하지 않는다.
- 새 코드에서 계정 로그인 성공·기기 준수·세션 유효성을 독립적으로 증명하지 않는다.

### 3순위 · 사건 근거와 AI 설명 흐름

- AI 설명 요청 전·요청 중 화면에서 **현재 선택된 사건 ID**를 보여 주어 선택 대상을 명확히 한다.
- 근거가 검증된 참고 설명에만 성공 표시를 허용하고, 실제 정책 판정·조치 효과의 독립 증거가 아니며 자동 집행되지 않는다는 경계를 추가한다.
- 실제 AI 게이트, 운영 계정, 실행 엔진·보안 조치는 수정하거나 호출하지 않는다.

## 5. 새 브랜치 재현 방법 (기존 폴더 절대 보존)

**CMD 새 창**에서 아래 명령을 사용한다. 대상 폴더가 이미 존재하면 지우지 말고 먼저 다른 폴더명을 택한다.

~~~bat
git clone --branch post22/timeline-state-ai-polish-20261026 --single-branch https://github.com/yeaun12/argos-security-agent.git "%USERPROFILE%\Documents\argos-post22-polish-20261026"
cd /d "%USERPROFILE%\Documents\argos-post22-polish-20261026\on-client"
git rev-parse HEAD
git status --short
node --version
node --check student\extension.mjs
node --test
~~~

예상 검증 항목: 새 개선 브랜치 SHA, 빈 `git status --short`, 문법 오류 없는지, 이전 42개 + 신규 12개 총 **54개** 테스트의 실제 PASS/FAIL 로그. **숫자는 실행 전 예상 개수일 뿐, 통과한 결과가 아니다.**

**예제 데이터만** 화면에서 확인할 때:

~~~bat
powershell -NoProfile -ExecutionPolicy Bypass -File ".\tools\start-alekov.ps1" -Demo -NoNativeHost -Port 5195
~~~

브라우저 `http://127.0.0.1:5195/`에서 (1) 보호 현황 상태 표시 (2) 학습 자료실 Demo 접근 허용 (3) 보안 기록 `event-01`의 발생일(UTC) 그룹·세 필터·상세를 확인한다. 기록은 1건이므로 다중 기록 정렬과 제외 필터의 브라우저 시연이라고 주장하지 않는다. 서버 종료: 실행한 CMD에서 `Ctrl+C`. 원본 `5194` 서버는 그대로 둔다.

## 6. 포장 목표 (이번 코드 수정 대상은 아님)

선택된 포장 순서는 **기본 포장 → Inno Setup 사용자 단위 설치(`setup.exe`)**이다. 현재 이 브랜치에는 설치 스크립트·실행 호스트·완성된 `setup.exe`가 없으며 실제 설치·제거·재실행 검증도 없다. 설치형은 개발용 `tools/start-alekov.ps1`과 다른 실행 계약을 요구할 수 있으므로, 포장 파일과 런타임·권한·데이터 보존/제거 정책을 먼저 검토해 **별도 승인**받은 뒤 구현한다. 인증 비밀·SDP 설정·개인 Native Host 보관 파일은 포장하지 않는다.
