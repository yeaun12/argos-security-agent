# ARGOS v1.1 — 근거 중심 조사 콘솔 / 제출 범위

## 목표

ALEPH 학생 영역의 정보 구조를 **상태 확인 → 사건 선택 → 근거/규칙 검토 → AI 참고 설명 → 사람의 결정**으로 연결한다. 전체 XDR/SOC 운영 제품이라고 주장하지 않는다.

## 수정 범위

- `student/extension.mjs` — `renderStatus`에 사용자 범위 기기·세션·알림의 근거 기반 우선 확인 카드; `renderEvents`에 현재 전달된 기록 안에서만 검색하는 입력, 사건 선택 시 조사 가이드; `renderExplanation`에 **기존 입력·결과 검증을 통과했을 때만** 나타나는 AI 브리핑.
- `public/style.css` — 포트폴리오용 점진적 CSS. 공식 제공 화면이나 설치형 앱이 동일 CSS를 사용할 것이라고 가정하지 않는다. 학생 기능은 이 스타일 없이도 동작한다.
- `test/argos-v11-investigation.test.mjs` — 소스 계약, Demo/확인 불가, 실제 받은 상태, 로컬 기록 검색, 사건 선택, AI 브리핑 검증 분리.
- 이 문서.

## 건드리지 않은 것

`public/app.js`, `public/index.html`, `src/**`, `tools/**`, `vendor/**`, 기존 학생의 다른 함수, 개인 Native Host 자격, ALEPH 계정 승인/AI 승인 경로, 원격 데이터, 설치 프로그램, 보안 조치 전송 경로. `student/appearance.json` 스키마가 현재 원본 시작 틀에서 확인되지 않았으므로 임의로 추가하지 않았다.

## 근거와 한계

- 기기·세션: `connected` 및 해당 리소스가 `ok`이며 실제 목록이 있는 경우에만 목록의 상태를 요약. 주의 상태는 `noncompliant`, `expired`, `revoked` 등이 **입력에 실제로 있을 때**만 표시. 전부 `compliant`라도 전체 시스템이 안전하다고 판단하지 않는다.
- 알림: 연결된 범위에서 전달된 배열만 집계. 배열 부재·Demo·미연결은 `확인 불가`와 분리하여 표시.
- 기록: 현재 전달받은 본인 최근 최대 40건 안의 `event.at` 발생 시각과 근거/규칙. 클라이언트 검색은 전송하지 않으며 전체 로그를 검색하거나 사건을 탐지하지 않는다. 조회 시각과 발생 시각은 다르다.
- AI: 기존 계약 검사(`executed:false`, `requiresHumanConfirmation:true`, 근거 ID 결속, 지원 조치/모드 검사)가 **통과할 때만** 요약을 표시한다. 원천 사실 판정이나 실제 보안 조치의 성공 증거가 아니다. 모델 호출 성공은 별도 검증 필요.
- Windows CPU/메모리/디스크는 기존 제공 PC 실측 기능이며 학생이 구현한 위 카드와 다른 데이터 출처다. 기존 그래프는 받아 온 실측만 표시하고 네트워크/방화벽 로그 집계를 침해 판정으로 변환하지 않는다.

## 제출 전 실행 검증

1. `node --check student/extension.mjs`
2. `node --check public/app.js`
3. `node --test` (기존 105건 + 이번 테스트 8건 = 예상 113건)
4. `git diff --check`
5. Demo / 일반 모드 모두에서 기록 검색, 사건 선택, 상태 카드, 실제 계정 연결 유지 확인.
6. 비밀값·개인 설정·로컬 백업 폴더가 커밋되지 않도록 `git status --short`와 스테이징 목록 검토.

**공식 제출과 포트폴리오 디자인은 구분**: 공식 수업 환경의 제공 UI/설치형 반영은 승인된 환경에서 실측 확인해야 하며, 제출 대상은 검증된 GitHub 커밋이다. 기존 22단계 및 총공세 SHA는 수정하지 않는다.
